# 版本管理说明

分享版于 2026-09-16 建立版本控制，此前改动只落盘、改坏无法回滚。

- 分支：`main`　远端：**无**（纯本地，用于回滚保护）
- 基线提交：`chore: 建立版本基线（分享版初始快照）`，120 个文件
- 与源码仓库 `Desktop\工作文件夹\MorningBoard` 是**两套内容不同源的代码库**，互不推送

## 日常三条命令

```bash
git status          # 改了什么、工作区干不干净
git diff            # 具体改了哪几行
git add -A && git commit -m "说明"   # 存一个还原点
```

改动前先跑 `git status`：工作区干净时才容易分辨"哪些是本次改的"。

## 回滚

| 场景 | 命令 |
|---|---|
| 改坏一个文件，还没提交 | `git checkout -- app/ui/tabs/news.py` |
| 改坏一堆文件，还没提交 | `git reset --hard HEAD` |
| 已提交但想撤销这次提交（保留改动） | `git reset --soft HEAD~1` |
| 看某次提交改了什么 | `git show <提交号>` |
| 想退回更早的版本 | `git reset --hard <提交号>`（先 `git log --oneline` 找） |

`git reset --hard` 会**丢弃未提交的改动**，确认不需要了再执行。

## 什么不入库

`.gitignore` 与源码仓库完全一致，以下刻意忽略：

- `cache/` —— 运行时生成（`today.json`、`ai_weekly/` 等），每次跑都会变
- `__pycache__/`、`MorningBoard*.spec`、打包产物、`*.lnk`
- `cache/today.json` 的修改时间可用来判断哪份副本在跑（另一份过期副本路径不含 `(1)`）

`config.json` **可以入库**：其中不含密钥，DeepSeek key 走 `DEEPSEEK_API_KEY` 环境变量，
`mail.auth_code` 为空。

## 本仓库的 git 配置（刻意设的，别覆盖）

```bash
user.name / user.email   # 只写在仓库级，不污染全局
core.autocrlf = false    # Windows 下防止 CRLF 污染，否则每次 diff 满屏
core.quotepath = false   # 否则中文路径会显示成八进制转义
```
